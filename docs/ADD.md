# Darwin Skill 2.0 公理设计文档

本文档根据 `docs/URD.md` 推导功能需求、设计参数和设计矩阵。当前版本已纳入个体化领域评分标准、领域调查研究、领域评分标准质量评估和用户确认冻结要求。

## 1. 设计结论

| 项 | 结论 |
| --- | --- |
| 设计类型 | 下三角矩阵，属于可按顺序执行的解耦设计。 |
| 执行顺序 | ADD-DP-001 → ADD-DP-002 → ADD-DP-003 → ADD-DP-004 → ADD-DP-005 → ADD-DP-006 → ADD-DP-007 → ADD-DP-008 → ADD-DP-009 → ADD-DP-010 → ADD-DP-011 → ADD-DP-012 → ADD-DP-013 → ADD-DP-014 |
| 不规则耦合 | 未发现必须接受的不规则耦合。 |
| 主要原因 | 新增研究和质量评估要求改变了领域评分流程顺序。把领域研究、领域评分标准生成、领域测试 prompt、评分标准质量评估、用户确认冻结、正式评分和综合决策拆开后，后续设计参数不会反向修改前置功能需求。 |

## 3. 设计参数

| ID | 设计参数 | 职责 |
| --- | --- | --- |
| ADD-DP-001 | 阶段检查点协议 | 定义何时暂停、展示哪些信息、用户确认后才能继续。 |
| ADD-DP-002 | 目标范围解析规则 | 从用户请求中得到待处理 skill 列表、运行位置和异常情况。 |
| ADD-DP-003 | 领域研究获取与记录规则 | 按能力优先级选择研究路径，生成 `domain-research.md` 和 `domain-research-meta.json`，记录方法、来源、证据空白和置信度。 |
| ADD-DP-004 | 研究驱动的领域评分标准生成规则 | 从目标 skill、用户目标、研究结果、样本和失败案例生成 `domain-rubric.md`，并把维度与依据关联。 |
| ADD-DP-005 | 测试 prompt 集和维度匹配规则 | 生成、复用、展示和确认公共测试 prompt 与 `domain-test-prompts.json`，记录 prompt 覆盖的领域维度和风险。 |
| ADD-DP-006 | 领域评分标准质量评估规则 | 按 RQ1 到 RQ9 计算质量分，应用总分门槛、关键维度门槛、低置信度规则和模板污染规则。 |
| ADD-DP-007 | 领域评分确认与版本冻结规则 | 管理 `domain-rubric-meta.json`、用户选择、重新研究、重新生成、重新评估、版本变化、冻结和跳过领域评分。 |
| ADD-DP-008 | 效果验证执行规则 | 调用独立评审或执行干跑验证，并输出验证模式。 |
| ADD-DP-009 | 公共评分模型 | 按现有公共 rubric 计算 `common_score`、维度分和短板。 |
| ADD-DP-010 | 领域评分模型 | 按冻结的领域 rubric 计算 `domain_score`、hard gates 和领域失败说明。 |
| ADD-DP-011 | runtime 中立性扫描规则 | 扫描红灯项，输出命中项和优先修复建议。 |
| ADD-DP-012 | 单维度优化控制规则 | 根据公共评分、领域评分和 runtime 结果选择本轮唯一主要优化方向。 |
| ADD-DP-013 | 综合决策与历史记录规则 | 计算 `composite_score`，应用保留或回滚规则，并写入新版或旧版兼容记录。 |
| ADD-DP-014 | 成果卡片、报告与公开文档一致性规则 | 使用模板生成成果卡片，扩展报告，并检查 README、发布页、引用资料和 `SKILL.md` 的一致性。 |

## 5. 调整过程

### 5.1 初始拆分

初始方案把领域研究、领域评分标准生成、领域测试 prompt 和质量评估都放在原 ADD-DP-003 中，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| 研究路径选择和评分标准生成混在一起。 | 无法单独验证是否记录了研究方法、来源、证据空白和置信度。 |
| 领域测试 prompt 同时服务评分标准生成和质量评估。 | RQ8 测试 prompt 匹配度无法独立评分。 |
| 低质量评分标准的阻断规则和用户冻结规则混在一起。 | 质量不合格时仍可能进入用户冻结或优化循环。 |

处理：拆出 ADD-DP-003 领域研究、ADD-DP-005 测试 prompt 集和 ADD-DP-006 质量评估，把领域评分标准生成保留为 ADD-DP-004。

### 5.2 第一次调整

第一次调整后，质量评估和用户确认冻结仍放在同一个 DP 中，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| 质量评估应先给出 `accept`、`revise`、`reject` 或 `needs_user_confirmation`。 | 如果与用户选择混在一起，无法清楚表达质量门槛的自动阻断效果。 |
| 用户修改领域评分标准后必须重新评估。 | 如果冻结和评估不分离，重新评估触发条件不清楚。 |

处理：把质量评估定义为 ADD-DP-006，把确认、版本记录和冻结定义为 ADD-DP-007。

### 5.3 第二次调整

第二次调整后，领域评分标准质量结果没有进入综合决策，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| 低质量评分标准不得进入正式优化循环。 | 仅在冻结阶段处理不足以覆盖用户强制使用低质量评分标准的报告风险。 |
| 连续修订失败需要提示用户人工介入。 | 综合决策和报告需要读取质量评估结论。 |

处理：让 ADD-DP-013 综合决策读取质量评估和冻结状态；让 ADD-DP-014 报告输出研究和质量评估内容，但不反向修改评分标准。

### 5.4 第三次调整

第三次调整后，runtime 中立性扫描仍可能被放进优化控制内部，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| runtime 红灯项既是检查结果，也是优化优先级输入。 | 如果放在优化控制内部，会掩盖 runtime 修复与普通评分短板之间的顺序关系。 |

处理：保留 ADD-DP-011 runtime 中立性扫描规则，再由 ADD-DP-012 单维度优化控制规则读取其结果。调整后形成下三角矩阵。
