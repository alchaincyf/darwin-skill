# Darwin Skill 2.0 公理设计文档

本文档根据 `docs/URD.md` 推导功能需求、设计参数和设计矩阵。目标是把需求拆成可按顺序实现和验证的部分，并检查设计耦合。

## 1. 设计结论

| 项 | 结论 |
| --- | --- |
| 设计类型 | 下三角矩阵，属于可按顺序执行的解耦设计。 |
| 执行顺序 | ADD-DP-001 → ADD-DP-002 → ADD-DP-003 → ADD-DP-004 → ADD-DP-005 → ADD-DP-006 → ADD-DP-007 → ADD-DP-008 → ADD-DP-009 |
| 不规则耦合 | 未发现必须接受的不规则耦合。 |
| 主要原因 | 人工确认、目标范围、测试输入、效果验证、评分、runtime 检查、优化、记录、成果输出存在明确前后关系。把前置约束放在前面后，后续设计参数不会反向改变前面的功能需求。 |

## 3. 设计参数

| ID | 设计参数 | 职责 |
| --- | --- | --- |
| ADD-DP-001 | 阶段检查点协议 | 定义何时暂停、展示哪些信息、用户确认后才能继续。 |
| ADD-DP-002 | 目标范围解析规则 | 从用户请求中得到待处理 skill 列表、运行位置和异常情况。 |
| ADD-DP-003 | 测试 prompt 集规则 | 生成、复用、展示和确认测试 prompt。 |
| ADD-DP-004 | 效果验证执行规则 | 调用独立评审或执行干跑验证，并输出验证模式。 |
| ADD-DP-005 | 9 维评分模型 | 按 rubric 计算维度分、权重分、总分和短板。 |
| ADD-DP-006 | runtime 中立性扫描规则 | 扫描红灯项，输出命中项和优先修复建议。 |
| ADD-DP-007 | 单维度优化控制规则 | 根据评分和 runtime 结果选择本轮唯一主要优化方向。 |
| ADD-DP-008 | git 保留/回滚与历史记录规则 | 比较新旧分数，决定保留或回滚，并写入 `results.tsv`。 |
| ADD-DP-009 | 成果卡片与公开文档一致性规则 | 使用模板生成成果卡片，并检查 README、发布页、引用资料和 `SKILL.md` 的一致性。 |

## 5. 调整过程

### 5.1 初始拆分

初始方案把用户确认放在优化流程末尾，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| 用户确认会影响测试 prompt 是否可用。 | 后置 DP 反向影响 ADD-FR-003，矩阵右上区域出现 `X`。 |
| 用户确认会影响评分和优化是否继续。 | 后置 DP 反向影响 ADD-FR-004、ADD-FR-005、ADD-FR-007。 |

处理：把用户确认抽为 ADD-DP-001，并作为所有后续步骤的前置控制。

### 5.2 第一次调整

第一次调整后，评分模型仍同时承担测试执行和分数计算，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| 效果验证与评分计算混在一个 DP 中。 | 无法单独标注 `full_test` / `dry_run`，也无法单独检查独立评审要求。 |
| 评分模型同时决定优化输入。 | 难以判断分数变化来自测试输入、评审方式还是 rubric 权重。 |

处理：拆出 ADD-DP-004 效果验证执行规则，再由 ADD-DP-005 评分模型消费验证结果。

### 5.3 第二次调整

第二次调整后，runtime 中立性检查仍和优化方案混在一起，形成以下问题：

| 问题 | 影响 |
| --- | --- |
| runtime 红灯项既是检查结果，也是优化优先级输入。 | 如果放在优化规则内部，会掩盖 P0 修复与普通评分短板之间的顺序关系。 |

处理：拆出 ADD-DP-006 runtime 中立性扫描规则，再由 ADD-DP-007 单维度优化控制规则读取其结果。调整后形成下三角矩阵。
