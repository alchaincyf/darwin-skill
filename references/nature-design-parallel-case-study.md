# 前端类 Skill 并行化改造案例 — nature-design-prototype

## 背景

nature-design-prototype 是一个前端原型生成 skill，基于自然系设计系统（温暖乳白+森林幽绿+沙滩米色+陶土橙红）将产品需求转化为可直接运行的 HTML 高保真交互原型。

经过 Darwin 优化后，该 skill 从 v1.0（59.2分）提升到 v2.0（89.5分），主要改进包括：
- 组件选择决策树（3层决策）
- 非标准组件扩展指南（4个CSS模板）
- 响应式断点实现模板
- 检查点设计（CHECKPOINT）
- 失败模式三段式处理
- 反例黑名单（10条反模式）
- 多页面预览框架 preview-shell

## 并行化改造动机

用户要求："让这个 skill 在执行过程中，可以通过 spawn 子代理来并行完成任务，同时要引入交叉评审子代理，整体提升任务质量和任务速度。"

## 改造方案

### 核心设计

1. **判定条件**：单页需求 → 串行；多页需求（≥2页）→ 并行
2. **统一 Tokens 先行**：主 agent 先输出共享设计 Tokens，子代理只负责页面拼装
3. **交叉评审互审**：子代理 A 评审 B+C 的页面，避免自审盲区
4. **7步并行流程**：
   ```
   主agent解析 → 统一Tokens → 拆分任务
   → Spawn子代理并行生成 → 交叉评审 → 整合 → preview.html
   ```

### 新增内容

在 SKILL.md 中新增「并行生成模式（多页面加速）」章节，包含：

| 子章节 | 内容 |
|--------|------|
| 判定条件 | 单页/2-3页/≥4页的不同处理方式 |
| 并行生成流程 | 7步流程图（ASCII） |
| 子代理任务规范 | 完整上下文模板（含Tokens/需求/组件/状态/约束） |
| 交叉评审规范 | 7个评审维度 + 通过标准 + 输出格式 |
| 主agent整合规则 | 4步整合流程 |
| 并行模式触发词 | 4个自动触发关键词 |

### 交叉评审维度

| 维度 | 检查内容 | 通过标准 |
|------|---------|---------|
| 色彩一致性 | 色值是否来自统一Tokens | 无硬编码 |
| 间距一致性 | 是否使用8px网格 | 无随意px |
| 组件一致性 | 同类型组件跨页是否统一 | 样式一致 |
| 状态完整性 | 7种状态是否齐全 | 无遗漏 |
| 响应式一致性 | 断点是否统一 | 375/768/1024 |
| 动画一致性 | 时长/缓动是否统一 | 相同transition |
| 零依赖 | 是否有CDN | 无外部链接 |

## 体积控制挑战

改造后 SKILL.md 从 606行（v2.0）增长到 722行（v3.0），体积比 185.6%，超出 Darwin 建议的 150% 限制。

**原因**：并行化章节约 120行是增量功能，无法通过压缩CSS来削减。

**决策**：接受体积超标，因为：
1. 并行化是核心功能升级，不是冗余内容
2. 后续可考虑将并行章节拆分到 `references/parallel-mode.md`

## 关键教训

1. **并行模式不替代串行模式**：单页需求仍用原5步工作流，避免过度工程化
2. **统一Tokens是关键**：子代理只负责拼装，不各自定义Tokens，确保一致性
3. **交叉评审避免自审盲区**：互审机制比自审更能发现问题
4. **体积与功能的权衡**：核心功能升级可接受适度体积增长，但需记录并规划后续拆分
