## 7 轮优化详情

### Round 1: dim3 + dim4（Δ +9.6）

**改动**：新增「前置检查与失败处理」章节

```markdown
## 前置检查与失败处理

| 检查项 | 通过条件 | 失败触发条件 | Fallback 动作 |
|--------|---------|-------------|--------------|
| URL 有效性 | 用户提供有效 URL | 未提供 / 格式错误 / 404 | 🔴 STOP：礼貌请求URL |
| 网站可访问性 | browser_visit 成功 | 超时 / Cloudflare | 尝试 cache，仍失败→标注基于索引数据 |
| 竞对数量 | ≥5 家核心竞对 | <5 家 | 扩大搜索范围，仍不足→标注建议补充报告 |
| B2B 属性确认 | 明确 B2B 或混合 | 纯 B2C / 内容站 | 🔴 STOP：建议转用 B2C 工具 |
| 地理范围 | 明确目标市场 | 无标识 / 未指定 | 🔴 CHECKPOINT：询问 US/EU/China/全球 |
```

**效果**：dim3 3→8（+5），dim4 2→6（+4），dim2 8→9（+1）

## 关键经验

### 1. dim2/dim3/dim4 相关簇效应

修 dim3（失败模式）时，dim4（检查点）和 dim2（工作流）常跟着涨。
- Round 1 主攻 dim3，dim4 同步 +4，dim2 同步 +1
- **策略**：找最低维度时同时看相关簇，决定是否同步改，避免重复劳动

### 2. 干跑验证的局限性

dim8（实测表现）采用干跑验证（无子 agent），得分从 5.7→7.5，提升有限。
- 真实子 agent 测试可能发现更多问题
- **策略**：dry_run 比例 > 30% 时在 results.tsv 打 ⚠️，告知用户分数可能虚高

### 3. 文件大小监控

```bash
# 监控优化后文件大小（避免 > 150%）
original_size=$(git show HEAD~N:SKILL.md | wc -c)
current_size=$(wc -c < SKILL.md)
ratio=$(python3 -c "print(f'{current_size/original_size*100:.1f}')")
```

本次：21,963 → 26,977 bytes（+22.8%），远低于 150% 限制。

### 4. 环境依赖陷阱

- `bc` 缺失 → 用 Python 替代
- `git config user.email` 未配置 → commit 前自动配置
- Playwright/chromium 缺失 → 截图降级为 HTML 交付

**策略**：Darwin 执行时不假设环境有任意特定工具，一律准备 fallback。
